# Deployment Guide

Order matters: **database → backend → frontend → connect them.** Each step needs a URL or value from the previous one.

| Piece | Service | You get |
|---|---|---|
| Database | MongoDB Atlas | `MONGODB_URI` |
| Email | Brevo (or another provider) | `BREVO_API_KEY` + a verified sender |
| Backend | Render | `https://<name>.onrender.com` |
| Frontend | Vercel | `https://<name>.vercel.app` |

---

## 1. MongoDB Atlas: production database

Use the same free cluster as development, but a **separate database and a separate database user**. A mistake in development (or `npm run test:api`) can then never touch real users, and a leaked development password can't read production data.

### 1.1 Create a production database user

1. Atlas → your project → **Database Access** → **Add New Database User**.
2. Authentication: **Password**. Username: `otp-prod-app`. Click **Autogenerate Secure Password** and copy it somewhere safe.
   - Avoid characters like `@ : / ? # %` in passwords you type yourself. They break the URI unless URL-encoded. Autogenerated ones are safe.
3. **Database User Privileges** → **Specific Privileges** → **Add Specific Privilege**:
   - Role `readWrite`, Database `otpSend-prod`, Collection: *(leave empty)*.
   - This user can only read and write that one database. Even if its password leaks, your development data and the rest of the cluster stay safe.
4. **Add User**.

### 1.2 Allow Render to connect

1. Atlas → **Network Access** → **Add IP Address** → **Allow Access from Anywhere** (`0.0.0.0/0`) → Confirm.
2. Why: Render's free tier has no fixed outgoing IP address, so Atlas can't allow-list one. Protection comes from the strong, autogenerated password, and every connection is TLS-encrypted.

### 1.3 Build the connection string

Atlas → **Database** → **Connect** → **Drivers** → copy the string. Then:

```
mongodb+srv://otp-prod-app:<password>@cluster1.xxxxx.mongodb.net/otpSend-prod?retryWrites=true&w=majority
                 user        password                cluster host  ^^^^^^^^^^^^ database name
```

- Replace `<password>`, including the `< >`.
- Add **`/otpSend-prod`** before the `?`. Without it, MongoDB silently uses a database called `test`.

### 1.4 Test it from your computer

1. Create `server/.env.production.local`. Git ignores it. It holds one line:

   ```
   MONGODB_URI=mongodb+srv://otp-prod-app:...@.../otpSend-prod?retryWrites=true&w=majority
   ```

2. Run:

   ```bash
   cd server
   npm run db:check:prod
   ```

   Expected output: `Database: otpSend-prod`, the indexes for `users`, `otps` and `passwordresets`, `Users: 0`, and `OK - connection works.`

This connects with the production credentials and creates the indexes (unique emails, TTL auto-delete) before the first real user arrives.

> Keep this URI. You will paste it into Render as `MONGODB_URI` in the next section.
